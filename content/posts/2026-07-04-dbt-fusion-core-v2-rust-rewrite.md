# dbt Fusion and Core v2.0: The Rust Rewrite, Free Binary, and AI Integration

dbt Fusion is dbt Labs' proprietary engine that extends the open-source dbt Core foundation with SQL comprehension, column-level lineage, static analysis, and AI-ready metadata. Written in Rust, Fusion parses a 10,000-model project up to 30x faster than dbt Core v1.

dbt Core v2.0 (alpha, June 2026) is now built on the same Rust foundation as Fusion. The two-engine era is ending. Core and Fusion share the same runtime. Core v2.0 is fully Apache 2.0 licensed. Fusion extends that baseline with proprietary features.

## The Rust rewrite

```
dbt Core v1 (Python)        dbt Core v2.0 (Rust)        Fusion (Rust + Proprietary)
     │                              │                              │
     │  Python-based                │  Same Rust runtime            │  Same Rust runtime
     │  Slow parsing                │  30x faster                   │  30x faster
     │  No static analysis          │  Static analysis (Fusion)     │  Static analysis
     │  No column lineage           │  Column lineage (Fusion)      │  Column lineage
     │  Apache 2.0                  │  Apache 2.0                   │  Proprietary (free binary)
```

Key insight: Fusion code that was previously under ELv2 license has been relicensed to Apache 2.0 as dbt Core v2.0. Fusion continues to extend that baseline with proprietary features.

## Licensing: is it free?

| Distribution | License | Cost | What You Get |
|-------------|---------|------|-------------|
| dbt Core v2.0 | Apache 2.0 | Free | Rust-based runtime, faster parsing, basic features |
| Fusion binary | Proprietary (free use) | Free (no account needed) | Core v2.0 + SQL comprehension + column lineage + static analysis |
| Fusion premium | Proprietary (login required) | Free login or paid | Full column lineage, AI features, platform integration |

From dbt Labs: "You can still use the enhanced, precompiled Fusion binary completely for free. We think this is the best way to use dbt."

The practical answer: yes, you can use Fusion for free. Install it, use it locally and in production, no account needed. The binary is proprietary but free. The source code for the runtime is Apache 2.0 (in dbt Core v2.0). Some premium features (full column lineage visualization, AI capabilities) require a free login.

## What Fusion is designed for

Fusion is designed for modern data transformation where projects are large (thousands of models), SQL correctness is critical, lineage is required, AI agents need context, and development speed matters.

**Core capabilities:**

| Capability | Description |
|-----------|-------------|
| SQL comprehension | Native understanding of SQL across dialects, not just string manipulation |
| Static analysis | Compiles and validates all SQL before execution |
| Column-level lineage | Automatically generates column-to-column dependency tracking |
| Type inference | Detects data types from SQL expressions |
| Language server | Real-time validation in IDE (errors before hitting the warehouse) |
| Rust performance | 30x faster parsing than dbt Core v1 |
| State-aware orchestration | Only runs what's changed or stale |

**Static analysis modes:**

| Mode | What It Does | When to Use |
|------|-------------|-------------|
| off | Skip SQL analysis | Legacy projects, quick iteration |
| baseline | Analyze SQL, catch most errors | Recommended starting point for migration |
| strict | Analyze ALL SQL before execution | Maximum guarantees, required for some features |

Strict mode guarantees nothing runs until the entire project is proven valid.

## AI integration

Fusion's biggest differentiator for AI is its metadata layer, generated automatically at compile time.

**What gets generated at compile time (not by AI):**

```
Compile time (automatic):
├── Column-level lineage (every column → source columns)
├── Type information (inferred from SQL)
├── Dependencies (model → model, model → source)
├── Test coverage (which columns have tests)
└── Semantic definitions (metrics, dimensions)
```

This metadata is NOT generated by AI. It is generated by the SQL compiler. AI agents consume it as ground truth.

**Why this matters:** AI agents need accurate project context to generate correct code. Without column-level lineage, an agent guessing about column relationships will produce wrong code. Fusion's metadata is the map that makes AI reliable.

### dbt MCP Server

Fusion exposes project metadata via MCP (Model Context Protocol) for AI agents:

```
AI Agent (Claude, Codex, Cursor)
    │
    ├── MCP Protocol
    │
    └── dbt MCP Server
        ├── List models
        ├── Get column lineage
        ├── Get model dependencies
        ├── Run dbt commands
        └── Query metadata
```

Supported clients: Claude Desktop / Claude Code, Cursor, VS Code, any MCP-compatible agent.

Setup for Claude Code:

```json
{
  "mcpServers": {
    "dbt": {
      "command": "uvx",
      "args": ["dbt-mcp"],
      "env": { "DBT_HOST": "your-dbt-host" }
    }
  }
}
```

### dbt Wizard (AI agent)

dbt Wizard is an AI agent built into the dbt Studio IDE that uses Fusion's metadata:

| Capability | Description |
|-----------|-------------|
| Autonomous model generation | Build new models from natural language |
| Refactoring | Restructure existing models with AI guidance |
| Multi-step workflows | Complex changes across multiple files |
| Error diagnosis | Classify and fix errors automatically |
| Migration assistance | Migrate projects from Core v1 to Fusion |

dbt Wizard reads the project's metadata (lineage, tests, semantic definitions). It knows your data, not just your code. It generates SQL grounded in actual schema and lineage. It validates changes against the full project before running.

## Architecture

```
dbt Core v2.0 (Apache 2.0)
  Rust Runtime (open source)
  ├── Project parser
  ├── Jinja renderer
  ├── SQL compiler (basic)
  └── Execution engine

dbt Fusion (Proprietary)
  Fusion Extensions (proprietary)
  ├── SQL comprehension (multi-dialect)
  ├── Static analysis (baseline/strict)
  ├── Column-level lineage (automatic)
  ├── Type inference
  ├── Language server (IDE integration)
  ├── State-aware orchestration
  └── AI metadata layer

  Premium Features (login required)
  ├── Full lineage visualization
  ├── dbt Wizard (AI agent)
  ├── Platform-connected workflows
  └── Advanced MCP capabilities
```

## Migration path

```
Current: dbt Core v1 (Python)
    │
    ├── Option A: Stay on v1 (deprecated, no new features)
    │
    ├── Option B: Upgrade to dbt Core v2.0 (Apache 2.0)
    │   └── Same Rust runtime, basic features
    │
    └── Option C: Upgrade to Fusion (recommended)
        └── All Core v2.0 features + SQL comprehension + lineage + AI
```

Migration tool: `dbt parse --use-v2-parser` (checks compatibility). Migration skill: `migrating-dbt-core-to-fusion` (AI-assisted).

**Breaking changes in v2.0:** deprecated flags removed, stricter validation on erroneous inputs, changed behavior for some edge cases, new relation object resolution at parse time.

## Practical recommendations

| Scenario | Recommendation |
|----------|---------------|
| New project | Start with Fusion — best free dbt experience |
| Existing v1 project | Run `dbt parse --use-v2-parser` to check compatibility, then upgrade |
| Need open-source only | Use dbt Core v2.0 (Apache 2.0) — lose Fusion features |
| AI agent integration | Use Fusion + MCP server + dbt Wizard |
| Large project (1000+ models) | Fusion's 30x speed improvement is significant |
| Need column lineage | Fusion (Core v2.0 doesn't include it) |

## Anti-patterns

| Anti-Pattern | Why It Fails | Better Approach |
|-------------|-------------|-----------------|
| Assuming Fusion = dbt Core | Fusion has proprietary features beyond Core | Understand the licensing and feature differences |
| Ignoring static analysis | SQL errors hit production | Enable baseline mode at minimum |
| Not using lineage | AI agents guess about column relationships | Enable column-level lineage for AI workflows |
| Upgrading without testing | v2.0 has breaking changes | Run `dbt parse --use-v2-parser` first |
| Building from Core source | Lose Fusion's proprietary features | Use Fusion binary (free) unless you need Apache 2.0 |
